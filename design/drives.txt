Additional drives
=================

Windows Settings > Additional drives configures fixed folder letters,
four raw hard-disk image slots and floppy A/B. Changes apply at the next
start. Removing a mapping keeps the host data. The editor edits a draft;
Cancel in either dialog discards changes. Each CPU edition has separate
program, settings, logs, shortcuts and default drive C folders.

Host folders
------------

C remains the boot folder. D through Z are explicit additional mappings,
except U, reserved for FreeMiNT's unified filesystem. One confined helper
per folder serves the existing v1 protocol and optional directory batching.
The legacy shinogi.hostfs port names C; shinogi.hostfs.d through .z name
additional letters, independent of transport order. All ports share one
virtio-serial controller appended after the existing display/input devices.

The guest keeps per-drive transport queues, receive storage, directory page
cache and current path. Open files and DTA scans retain their drive. The
shared directory snapshot records its drive and is rebuilt when another
scan displaced it. Channel death preserves drive ownership so calls cannot
fall into stock FAT routing or accidentally close another helper's handle.
Control RX has32 descriptors. DEVICE_ADD messages are drained before each
PORT_READY reply, preventing QEMU from dropping names during enumeration.
Read-only helpers refuse all mutation operations and skip attribute repair.

Hard-disk images
----------------

Up to four existing, formatted raw .img/.hdf files use explicit format=raw
and cache=writethrough. QEMU keyval commas are escaped and Windows paths
are quoted. Settings rejects duplicate backing-file identities, malformed
paths and device paths. Read-only is the default. Partitions consume free
letters, skipping C, mapped folders and U; images may have several partitions.
The guest understands existing Atari/DOS partition and FAT12/FAT16 layouts.

Standard virtio-blk GET_ID identifies launcher serials shinogi.disk1..4,
keeping image slot order independent of transport discovery. These tagged
image units may write; ordinary untagged/vvfat devices still follow the
disabled developer write switch. VIRTIO_BLK_F_RO is negotiated and enforced
per device even when write support is enabled. Host folders never use vvfat.

Floppy images
-------------

Formatted raw .st/.img sector images provide actual BIOS A/B semantics.
Initial geometries are720KB and1.44MB,512-byte sectors,80 tracks,two sides.
Settings validates the size and boot geometry. Stable GET_ID serials
shinogi.floppya/b route these units outside hard-disk partition scanning.
BIOS and XBIOS reads/writes use the selected image; read-only returns EWRPRO.
Flopver uses sector reads; formatting through a controller is unsupported.

Images are fixed for an emulator run: Mediach reports no external change,
and restarting rebuilds BIOS/BPB and filesystem cache state. Tests swap
both media and geometries across restarts on EmuTOS and FreeMiNT. Live QMP
insert/eject requires explicit backend notification/cache invalidation before
it can be exposed. MSA compression and STX/protected-disk controllers remain
separate work, outside this initial sector-image path.

Validation
----------

See tests/drives/README.txt for independent host content/hash/fsck checks,
reopen and restart-swap tests, all-folder capacity tests and Windows dialog
and side-by-side installer lifecycle checks. These tests use disposable
copies of the system tree and fresh images; they never write to a user disk.
